# WhatsApp Drone Monitor

Локальний Python-бот, який слідкує за груповими чатами WhatsApp вашого
підрозділу БпЛА, розпізнає повідомлення про **втрату дронів** і
**нештатні ситуації**, веде облік **скільки бортів зараз на позиції** по
кожній групі, і шле короткі звіти/алерти адміністратору тим самим WhatsApp.

## Як це працює

- `src/whatsapp_client.py` — керує реальним браузером Chrome, залогіненим у
  web.whatsapp.com (через Selenium), читає нові повідомлення в чатах і шле
  текст у відповідь.
- `src/parser.py` — за ключовими словами класифікує кожне повідомлення:
  втрата дрона / нештатна ситуація / виліт (зайняв позицію) / повернення /
  інше.
- `src/state.py` — тримає лічильник "на позиції" по кожній групі + журнал
  втрат і нештатних ситуацій, зберігає в `state.json` (переживає рестарт).
- `src/reporter.py` — формує текст короткого звіту й миттєвого алерту.
- `src/monitor.py` — головний цикл: опитує чати, оновлює стан, шле алерти
  одразу при втраті/НС, шле періодичний звіт і відповідає на команду
  `звіт`/`статус` від адміністратора.

## Встановлення

```bash
cd whatsapp_drone_monitor
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp config.example.yaml config.yaml
```

Відредагуй `config.yaml`:
- `chats` — точні назви WhatsApp-чатів твоїх груп (як вони підписані у
  списку чатів) і як їх позначати у звітах.
- `admin_chat` — куди слати звіти й алерти. Найпростіше — чат "Ви"
  (Message yourself) у власному акаунті адміністратора.

Потрібен встановлений Google Chrome на машині, де буде працювати бот.

## Запуск

```bash
python run.py
```

При першому запуску відкриється вікно Chrome з QR-кодом — відскануй його
у WhatsApp на телефоні (Пов'язані пристрої). Сесія збережеться в
`chrome_profile/`, тож повторне сканування не знадобиться, поки сесію не
розлогінять з телефону.

**Використовуй окремий Chrome-профіль лише для бота** (це вже налаштовано
через `chrome_profile_dir`) — не той, яким користуєшся щодня: одночасний
запуск Chrome з одним user-data-dir з двох процесів конфліктує.

## Команди адміністратора

Напиши в `admin_chat` (той самий чат, куди бот шле звіти):
- `звіт` або `статус` — миттєвий короткий звіт по всіх групах.

Перший звіт бот надсилає одразу після старту (щоб підтвердити, що він
живий і показати поточний стан), далі — раз на `report_interval_hours`.

## Формат звіту

```
📊 Звіт по БпЛА станом на 14:32 22.08.2026

На позиції зараз: 7 борт(и)
  ЖАБА: 2
  КОБРА: 3
  ШМЕЛЬ: 2

За останні 24 год: втрат — 1, нештатних ситуацій — 1
  ⚠️ Втрата [ШМЕЛЬ] 13:10 — втрата дрона FPV, координати...
  ⚠️ НС [КОБРА] 09:45 — обрив зв'язку, повернення на базу
```

При втраті/нештатній ситуації такий самий алерт (🚨) летить адміну одразу,
не чекаючи періодичного звіту.

## Налаштування розпізнавання

Ключові слова лежать у `src/config.py` (`DEFAULT_*_KEYWORDS`) і
підвантажуються з `config.yaml`, якщо там задані поля `loss_keywords`,
`incident_keywords`, `launch_keywords`, `return_keywords`. Це проста
евристика за підрядками — вона не зрозуміє нестандартні формулювання чи
скорочення. Періодично переглядай `state.json` і сирі повідомлення в логах
на предмет пропущених випадків і доповнюй список слів.

## Важливі застереження

1. **Це неофіційна автоматизація особистого WhatsApp**, а не офіційний
   WhatsApp Business Cloud API. Meta забороняє автоматизований /
   неофіційний клієнтський доступ до WhatsApp у своїх умовах
   використання — є ризик, що номер, з якого працює бот, буде обмежено
   чи заблоковано за підозрілу активність. Для критичного застосування
   варто:
   - використовувати окремий, не критичний для інших цілей номер;
   - або в перспективі перейти на офіційний WhatsApp Business Platform
     (Cloud API) — стабільніший, але вимагає верифікації бізнесу і вже не
     є суто "локальним" рішенням.
2. **`chrome_profile/` = активна сесія WhatsApp** (еквівалент пароля) —
   вона в `.gitignore` і не повинна ніде публікуватись чи копіюватись.
   Те саме стосується `config.yaml` (реальні назви чатів/груп) і
   `state.json` (журнал втрат/НС).
3. **Приватність**: люди в моніторингових чатах мають знати, що
   повідомлення читає автоматична система і передає адміністратору.
4. **Крихкість DOM-селекторів**: WhatsApp Web регулярно змінює розмітку.
   Якщо бот перестав бачити повідомлення чи чати — онови селектори у
   словнику `SELECTORS` на початку `src/whatsapp_client.py`.
5. Розпізнавання "на позиції" рахує **лише те, про що написали в чаті**
   (виліт/повернення/втрата) — це не telemetry з самих дронів, а зведення
   людських повідомлень, тому точність залежить від дисципліни звітування
   груп.

## Тести

Логіка розпізнавання і облік стану не залежать від браузера й тому
покриті тестами:

```bash
python3 -m unittest discover -s tests -v
```

(Частина з WhatsApp/Selenium в `whatsapp_client.py` тестується лише
вручну — живого WhatsApp-сеансу для автотестів немає.)

## Можливі наступні кроки

- Дедублікація повідомлень за атрибутом `data-id` DOM-вузла (якщо
  присутній у вашій версії WhatsApp Web) замість поточного порівняння за
  текстом останнього повідомлення.
- Класифікація повідомлень через LLM (Claude) замість ключових слів —
  краще розуміє довільні формулювання, коштує дорожче й повільніше за
  прямий підрядковий пошук.
- Ручна команда корекції лічильника (`встановити ШМЕЛЬ 3`) на випадок,
  якщо якесь повідомлення не розпізналось і рахунок розійшовся з
  реальністю.
