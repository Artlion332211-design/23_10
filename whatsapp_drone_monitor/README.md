# WhatsApp Drone Monitor

Локальний Python-бот: читає групові чати WhatsApp вашого підрозділу БпЛА,
знаходить у повідомленнях серійні номери бортів зі статусними позначками
(**на ремонт** / **втрата**), знаходить цей борт у робочій Google-таблиці
**«РР-БпЛА»** за серійним номером і міняє клітинку СТАТУС. На запит чи за
розкладом шле адміністратору короткий звіт (живі дані з листа «На
позиції» + журнал останніх змін статусів).

## Що саме розпізнається

Перевірено на твоїх реальних прикладах повідомлень (`tests/test_parser.py`
містить їх дослівно):

1. **Інвентарний перелік з позначкою біля серійника** — решта списку
   ігнорується, спрацьовує лише анотований рядок:
   ```
   1581F7FVC25AC00DTHLW - (Знімаємо на ремонт)
   ```
2. **Розгорнутий звіт про втрату** (весь блок «Втрата борта: ... Причина:
   ...») — витягуються пілот, дата, час, координати, причина:
   ```
   Втрата борта:
   М4Т
   1581F7K3C265S00DFSGJ
   Дата 20.08.26
   ...
   Причина: Почало трусити камеру і сів на дерево
   ```
3. **Голий серійник + фраза на наступному рядку**:
   ```
   1581F7FVC264P00DVWTP
   Передали на ремонт Коброю 1
   ```

Просте перерахування бортів у щоденній інвентаризації (без позначки)
**не чіпає статус** — інакше кожен такий перелік перезаписував би СТАТУС
усім перерахованим бортам.

## Google-таблиця

Бот знайдений і перевірений на вашій живій таблиці **«РР-БпЛА»**
(`1zPdNEJktdkuov_ljo-0HGCp69RloUe4Evx4XVB7nasw`) — серійники з твоїх
прикладів (Шмель, Сімсон2) там уже є, на листах по моделях (`DJI Matrice
4T`, `DJI Matrice 4E`, ...) з колонками `Марка дрону, Серійний номер,
Розташування, Облікований / Не облікований, СТАТУС, Дата отримання,
Додаткова примітка`.

Бот шукає серійник по всіх листах книги (або лише перелічених у
`model_sheets`), і **міняє лише клітинку СТАТУС + дописує в «Додаткова
примітка»** — ніколи не додає/не видаляє рядки чи колонки, щоб не
зачепити формули на листі «На позиції» (судячи з даних, він порахований
формулами з таблиць по моделях, тому оновлення СТАТУС в моделі має
автоматично підтягнутися і туди).

**Обов'язково звір значення в `config.yaml` (`status_repair`,
`status_lost`) з реальним випадаючим списком у колонці СТАТУС.** У живих
даних станом на зараз трапляються `"потрібен ремонт"` (борт ще на позиції
групи, щойно позначений) і окремо `"В ремонті"` (борт вже фізично на
Інженерці) — я поставив за замовчуванням саме `"потрібен ремонт"`, бо
повідомлення в чаті описують момент здачі/зняття борта групою, а не факт,
що він уже в майстерні. Для втрати в старих копіях таблиці зустрічалось
і `"втрачено"`, і те, що ти написав, `"Втрата"` — уточни точний рядок з
дропдауна і виправ у конфігу, бо Sheets звірює його дослівно.

## Встановлення (крок за кроком)

```bash
cd whatsapp_drone_monitor
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp config.example.yaml config.yaml
```

### 1. Сервісний акаунт Google (для запису в таблицю)

Бот працює без людини, тому логінитись твоїм особистим Google-акаунтом
через браузер щоразу не варіант — потрібен **сервісний акаунт**:

1. https://console.cloud.google.com/ → створи проєкт (або обери наявний).
2. APIs & Services → Library → увімкни **Google Sheets API**.
3. APIs & Services → Credentials → Create Credentials → **Service
   Account** → дай будь-яке ім'я → Create and Continue → Done.
4. Відкрий створений сервісний акаунт → вкладка **Keys** → Add Key →
   Create new key → **JSON** → файл завантажиться на твій комп'ютер.
5. Поклади цей файл як `whatsapp_drone_monitor/credentials.json`
   (шлях налаштовується полем `credentials_path` в `config.yaml`).
6. Відкрий сам JSON-файл, знайди поле `client_email` (виглядає як
   `xxx@xxx.iam.gserviceaccount.com`).
7. Відкрий таблицю **«РР-БпЛА»** в Google Sheets → кнопка **Share** →
   встав цей `client_email` → права **Editor** → Send.

Перевір, що все спрацювало, без запуску WhatsApp:

```bash
python check_sheets.py
```

Має вивести список листів книги та вміст «На позиції».

### 2. WhatsApp

Потрібен встановлений Google Chrome на машині, де працюватиме бот, і
телефон з WhatsApp під рукою для одноразового сканування QR.

Відредагуй у `config.yaml`:
- `chats` — точні назви WhatsApp-чатів твоїх груп.
- `admin_chat` — куди бот шле алерти й звіти (напр. чат "Ви" / Message
  yourself).

```bash
python run.py
```

Відкриється Chrome з QR-кодом — скануєш у WhatsApp (Пов'язані пристрої).
Сесія збережеться в `chrome_profile/`, повторно сканувати не треба, поки
сесію не розлогінять з телефону. **Використовуй окремий Chrome-профіль
лише для бота** (уже так налаштовано) — не той, яким користуєшся щодня.

## ⚠️ Про "розгорни на цій машині"

Я протестував і повністю перевірив тут усе, що можна перевірити без
живого WhatsApp-акаунта й без ключа сервісного акаунта:
- логіку розбору повідомлень — **на твоєму реальному тексті дослівно**
  (усі три статусні події розпізнаються правильно, інвентарні списки не
  чіпаються);
- логіку пошуку/оновлення в таблиці — юніт-тестами з фейковим Sheets;
- повний конвеєр Monitor (парсинг → запис у таблицю → алерт адміну →
  журнал) — інтеграційним тестом;
- що Selenium дійсно може підняти справжній Chromium у цьому контейнері
  (дійшло до запуску сесії браузера; впало тільки на неспівпадінні версій
  chromedriver/Chromium, які тут просто не призначені одне для одного —
  це нерелевантно для твоєї машини з нормальним Chrome).

Чого я **не можу** зробити з цієї хмарної сесії:
- відсканувати QR WhatsApp — для цього потрібен твій телефон;
- створити сервісний акаунт Google — це дії в твоєму Google Cloud
  консолі, я не маю до нього доступу;
- лишити бота працювати "назавжди" — це ізольований контейнер, який
  прибирають після завершення сесії; для цілодобового моніторингу бот має
  жити на твоїй завжди-увімкненій машині (ПК, сервер, Raspberry Pi).

Тобто "готове рішення" тут — це повністю написаний, протестований код +
покроковий інструктаж вище. Сам запуск із реальним WhatsApp і реальним
записом у таблицю має відбутися на твоїй машині — там, де є і телефон
для QR, і постійна робота 24/7.

## Команди адміністратора

Напиши в `admin_chat`:
- `звіт` / `статус` / `на позиції` — миттєвий звіт: живі дані з листа «На
  позиції» + журнал змін статусів за останні 24 год.

Перший звіт бот надсилає одразу після старту, далі — раз на
`report_interval_hours`.

## Крихкість і що переглядати з часом

1. **DOM-селектори WhatsApp Web** (`SELECTORS` на початку
   `src/whatsapp_client.py`) — WhatsApp міняє розмітку без попередження.
2. **Точні рядки статусів** (`status_repair`, `status_lost` в
   `config.yaml`) — мають дослівно збігатися з дропдауном у колонці
   СТАТУС.
3. **Ключові фрази** розпізнавання ремонту/втрати (`REPAIR_PHRASE_RE`,
   `LOSS_PHRASE_RE` в `src/parser.py`) — розраховані на побачені
   формулювання ("Знімаємо на ремонт", "Передали на ремонт", "Втрата
   борта"). Нове формулювання, що не містить кореня "ремонт" чи
   "втрат"/"збит"/"підбит", розпізнано не буде.
4. **Серійник не знайдено в таблиці** — бот не мовчить, шле адміну алерт
   "❓ Не знайдено в реєстрі" замість тихо нічого не робити.

## Безпека

- `chrome_profile/`, `credentials.json`, `config.yaml`, `state.json` — усі
  в `.gitignore`. `credentials.json` дає повний доступ на запис до
  таблиці — стався до нього як до пароля.
- Це неофіційна автоматизація особистого WhatsApp (Selenium), не
  офіційний WhatsApp Business Cloud API — Meta забороняє таке в ToS, є
  ризик обмеження номера. Для критичного застосування варто окремий
  некритичний номер під бота.
- Учасники моніторингових чатів мають знати, що повідомлення обробляє
  автоматична система.
