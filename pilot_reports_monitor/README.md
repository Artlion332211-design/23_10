# Моніторинг звітів пілотів (WhatsApp)

Скрипт читає групу WhatsApp, де пілоти пишуть звіти про вильоти, і
сповіщає адміна, якщо якась позиція не подала звіт понад 24 години.
Працює через звичайний акаунт WhatsApp (WhatsApp Web), Business API не
потрібен.

## Як це працює

1. `monitor.py` відкриває web.whatsapp.com у керованому Chrome і чекає
   вхід (QR-код скануєте один раз — сесія зберігається в папці
   `wa_profile/`, тому при наступних запусках вхід відбувається автоматично).
2. Скрипт відкриває задану групу і кожні `scan_interval_seconds` секунд
   перевіряє нові повідомлення.
3. Повідомлення розпізнається як звіт позиції, якщо воно **починається**
   з позивного цієї позиції, наприклад:
   - `Шмель 4 вильоти`
   - `Кобра: 6`
   - `Нон стоп - 2`
   Число після позивного (якщо є) зберігається як кількість вильотів.
4. Кожні `alert_check_interval_seconds` скрипт перевіряє, чи є позиції,
   від яких немає звіту довше `report_timeout_hours` (за замовчуванням
   24 год), і надсилає повідомлення в чат `admin_chat_name` зі списком
   таких позицій. Повторний алерт по тій самій позиції не надсилається
   частіше, ніж раз на `alert_repeat_hours`.
5. Стан (час останнього звіту кожної позиції, вже оброблені повідомлення)
   зберігається в `state/state.json`, тож перезапуск скрипта нічого не
   втрачає.

## Встановлення

```bash
cd pilot_reports_monitor
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Потрібен встановлений Google Chrome (Selenium 4.15+ сам підбирає
відповідний chromedriver).

## Налаштування (`config.json`)

| Поле | Опис |
|---|---|
| `group_name` | Точна назва групи WhatsApp з пілотами |
| `admin_chat_name` | Чат, куди слати алерти (напр. власний чат "Особисті нотатки" або окремий чат з адміном) |
| `positions` | Список позицій: `name` — як позиція фігуруватиме в алертах, `aliases` — варіанти написання позивного, якими пілоти можуть починати повідомлення (нижній регістр, без урахування регістру) |
| `report_timeout_hours` | Через скільки годин без звіту вважати позицію "мовчазною" |
| `scan_interval_seconds` | Як часто перевіряти нові повідомлення в групі |
| `alert_check_interval_seconds` | Як часто перевіряти прострочені позиції |
| `alert_repeat_hours` | Мінімальний інтервал між повторними алертами по одній позиції |
| `chrome_profile_dir` | Папка для збереження сесії WhatsApp Web |
| `state_file` | Файл, де зберігається стан звітів |
| `headless` | `true`, щоб ховати вікно браузера (QR все одно треба відсканувати першого разу з `headless: false`) |

Відредагуйте список `positions` під реальні позивні вашого підрозділу.

## Запуск

```bash
python monitor.py
```

Перший запуск: скануєте QR-код у відкритому вікні Chrome. Далі скрипт
працює у циклі — тримайте процес запущеним (наприклад, у `tmux`/`screen`
на Linux, або як службу через `systemd`/NSSM/Task Scheduler).

## Обмеження

- Це неофіційна автоматизація WhatsApp Web через Selenium — вона працює,
  поки Meta не змінить розмітку сторінки. Якщо скрипт перестане бачити
  повідомлення чи не зможе відкрити чат, найімовірніше змінилися CSS-класи
  WhatsApp Web — селектори зібрані в функціях `open_chat`, `scan_messages`,
  `send_message` у `monitor.py`, їх треба буде підправити.
- Автоматизація особистого акаунта суперечить Умовам використання
  WhatsApp; ризик — тимчасове обмеження акаунта. Використовуйте для
  внутрішнього моніторингу власної групи, не для масових розсилок.
- Розпізнавання звіту прив'язане до тексту на початку повідомлення, а
  не до імені відправника — це надійніше, ніж парсити імена контактів,
  але вимагає від пілотів дотримуватись формату (позивний → число).
